# India Trader Scanner

The marketwide ORB path tries locally configured Upstox, then FYERS, before an explicitly unofficial Yahoo fallback. NSE public daily reports do not supply five-minute candles. Both account paths have offline tests but no live account validation.

This is the India adaptation of the upstream `trader-scanner` workflow. Its three commands are `universe`, `daily`, and `orb`. Run them from the repository root with `python -m india_trader scanner COMMAND`. The scanner reads charts and writes `trader/watchlist.json`; it does not select a trade, size an order, or place one.

- `universe` downloads the official NSE EQ security list into `trader/universe.txt`. Check the `retrieved_at` time. `--exchange BSE` reads BSE's public security-master ZIP and filters active one-share-lot cash equities; `--exchange BOTH` combines the lists. `--offline EQUITY_L.csv` and `--bse-zip SCRIP.ZIP` use saved exchange files. NSE is the default. BSE Yahoo chart coverage is poor in the tested symbols, so never imply that a BSE security list means a usable marketwide BSE price scan.
- `daily` reads three months of unofficial Yahoo daily closes in batches of 20. It checks 20-day closing breakouts, bull flags, 20-day average reclaim, RSI under 30, and oversold bounce. It excludes a forming daily candle. Run before the market opens or after the daily close. Use `--symbols RELIANCE,TCS`, `--watchlist FILE`, or `--limit N` to narrow the scan. The separate `daily-scan` command uses official NSE final Bhavcopy reports instead.
- `orb` scans completed five-minute bars from 09:15 IST. Stage one tries configured Upstox and FYERS charts before batched unofficial Yahoo fallback; `--max-source-fallback 0` means no cap on per-symbol Yahoo retries after a batch gap. Stage two confirms candidates against full OHLCV charts, again trying read-only Upstox/FYERS sources first. `--at 10:15` replays a completed cutoff; `--max-confirm 0` requests confirmation of every candidate. The default 200-confirmation cap can produce `PARTIAL`; always report `unconfirmed` and the fetched, usable, and scanned counts. `--offline PATH` supports saved Yahoo chart/spark JSON or `.json.gz` fixtures.
- `market-engine once|run|status` is the Stage 3 foreground controller. `run` waits outside eligible normal NSE sessions and rotates bounded batches of the NSE EQ universe during a session. It maintains a persisted candidate pool, monitors completed one- and five-minute broker candles, validates quotes and spread, expires old setups, and writes once-only `AWAITING_AI_REVIEW` events. It never selects a trade or sends an order. Start with `python -m india_trader market-engine once --symbols RELIANCE,TCS` for a bounded check; `run` stays in the foreground until stopped. No actual broker connectivity has been validated.

Default outputs include the source, exchange coverage, as-of time in IST, exact counts, and hits. `trader/watchlist.json` uses `hits[].symbol` for downstream workflows. `--no-write` inspects without replacing it; `--json` returns machine-readable results. A no-hit exit code is 1, so inspect the output rather than interpreting every nonzero code as a software crash.

Report a chart only as a **rule match**. Yahoo is unofficial, can be delayed or incomplete, and two Yahoo hosts are one provider. The scanner excludes missing five-minute slots and zero/missing volume from confirmed ORB hits. A 2026 NSE holiday list is built in; a refreshed public calendar closes known special sessions, but BSE-specific ORB timing, broad BSE candle coverage, and exchange reconciliation are not verified. Do not describe a historical replay as a live signal or promise returns.
