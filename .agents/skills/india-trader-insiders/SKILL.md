# India Trader Insider Tracker

Use `python -m india_trader insider-tracker index --symbol RELIANCE --read` to inspect public filings. `--symbol` repeats; `--member "name"` searches named persons within official XBRL; `--since YYYY-MM-DD`, `--year YYYY`, `--type '7(2)'`, `--limit N`, and `--as-of OFFSET_AWARE_ISO` filter results. `--json` exposes every filed field and official link. The current index is NSE's `corporates-pit-gg` Regulation 7(2)/7(3) feed; the older `corporates-pit` archive is also read. To check only the newer feed, add `--current-only`. The live index is finite; do not claim it covers every historical filing.

Use `python -m india_trader insider-tracker new --symbol RELIANCE --read` to show filings not already in `trader/state/insider-tracker.json`. The first check defaults to filings from the past 45 calendar days, recorded as a baseline for later checks; `--since` overrides it and `--today YYYY-MM-DD` sets the first-check date. `--dry-run` shows without marking filings seen. A repeat check returns exit code 1 when nothing is new. Save NSE public JSON responses as `current-SYMBOL.json` and `archive-SYMBOL.json`, plus linked XML under `xbrl/`, then use `--offline DIR` for reproducible checks. Without `--symbol`, offline indexes are `current.json` and `archive.json`. Failed XML reads remain eligible for a later new check.

Use `python -m india_trader insider-tracker fetch current:384 --symbol RELIANCE --json` for one indexed filing, or `parse PATH_TO_NSE_XBRL.xml --symbol RELIANCE --json` for a saved XML file. `--xml-dir DIR` saves successfully parsed source XML, `parse --filed YYYY-MM-DD` supplies a lag date if the XBRL lacks one, and `--tickers SYMBOL...` flags explicit watch symbols alongside `--portfolio`. Read the source URL before making a consequential claim. The tracker preserves the person's name and category, instrument, buy/sell/pledge type, quantity, **reported** value with its XBRL unit reference, transaction dates, market/off-market mode, intimation date, exchange, before/after holding, derivative fields and other facts. Quantity/value/holding fields stay as exact filed strings. A `value_unit_ref` of `shares` is a source data quality warning: do not silently label that amount INR. A filing can list multiple people or transactions. Current revisions retain their own IDs and links; verify which version supersedes which before summarizing.

The output shows calendar days from transaction end to filing. It does **not** label an Indian filing legally late from a US 45-day rule. `--portfolio trader/portfolio.json` flags matching paper holdings. A filing is historical public information, not a current entry signal. If the user asks about an entry, run the separate Scanner, Entry Timer, Budget and Risk workflows with their own data checks. No options, pledge, off-market transfer, or disclosure automatically becomes a share purchase. This skill never places an order. BSE-only companies and manual BSE filings require separately checked official sources; they are not silently represented as NSE coverage.
