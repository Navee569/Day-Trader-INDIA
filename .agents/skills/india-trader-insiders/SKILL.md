# India Trader Insider Tracker

Use `python -m india_trader insider-tracker index --symbol RELIANCE --read` to inspect public NSE filings. For BSE, use `--exchange BSE --symbol 539289 --since 2026-10-01 --read` with an official six-digit scrip code. `--symbol` repeats; `--member "name"` searches named persons within XBRL; `--since YYYY-MM-DD`, `--year YYYY`, `--type '7(2)'`, `--limit N`, and `--as-of OFFSET_AWARE_ISO` filter results. `--json` exposes every filed field and official link. The current NSE index is `corporates-pit-gg`; the older `corporates-pit` archive is also read, with month-by-month date filters when a symbol and older `--year`/`--since` are given. `--current-only` omits NSE archive. BSE uses its public PIT XBRL historical search and linked inline filings for up to 366 days per run. Neither venue is a verified complete archive.

Use `python -m india_trader insider-tracker new --symbol RELIANCE --read` to show filings not already in `trader/state/insider-tracker.json`. The first check defaults to filings from the past 45 calendar days, recorded as a baseline for later checks; `--since` overrides it and `--today YYYY-MM-DD` sets the first-check date. `--dry-run` shows without marking filings seen. A repeat check returns exit code 1 when nothing is new. Save NSE public JSON responses as `current-SYMBOL.json`, `archive-SYMBOL.json`, or dated `archive-SYMBOL-START-END.json`, plus linked XML under `xbrl/`, then use `--offline DIR`. BSE offline responses use `bse-CODE-START-END.html` plus linked inline files under `bse-ixbrl/`. Failed filing reads remain eligible for a later new check.

Use `python -m india_trader insider-tracker fetch current:384 --symbol RELIANCE --json` for one indexed filing, or `parse PATH_TO_NSE_XBRL.xml --symbol RELIANCE --json` for a saved XML file. `--xml-dir DIR` saves successfully parsed source XML, `parse --filed YYYY-MM-DD` supplies a lag date if the XBRL lacks one, and `--tickers SYMBOL...` flags explicit watch symbols alongside `--portfolio`. Read the source URL before making a consequential claim. The tracker preserves the person's name and category, instrument, buy/sell/pledge type, quantity, **reported** value with its XBRL unit reference, transaction dates, market/off-market mode, intimation date, exchange, before/after holding, derivative fields and other facts. Quantity/value/holding fields stay as exact filed strings. A `value_unit_ref` of `shares` is a source data quality warning: do not silently label that amount INR. A filing can list multiple people or transactions. Current revisions retain their own IDs and links; verify which version supersedes which before summarizing.

The output shows calendar days from transaction end to filing. It does **not** label an Indian filing legally late from a US 45-day rule. `--portfolio trader/portfolio.json` flags matching paper holdings. A filing is historical public information, not a current entry signal. If the user asks about an entry, run the separate Scanner, Entry Timer, Budget and Risk workflows with their own data checks. No options, pledge, off-market transfer, or disclosure automatically becomes a share purchase. This skill never places an order. BSE coverage requires an explicit scrip-code search; it is not silently represented as NSE coverage.
